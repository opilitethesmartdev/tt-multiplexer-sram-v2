# Whole-mux SPICE readiness

The standalone SRAM tests in the parent directory are not a whole-mux test.
A complete transistor-level simulation must use the selected build's routed
top-level connectivity **and** verified transistor subcircuits for all
electrically relevant instantiated macros and standard cells.

## What is actually available

The attached `artifacts/` files are unchanged, gzip-compressed files from
[GDS run 45835066447](https://github.com/opilitethesmartdev/hackclub-asic-pg/actions/runs/45835066447)
(shuttle `52bf1d8`, mux `2914d8a`), not the later candidate. This flow's
SPICE was generated by **Magic extraction of the OpenROAD DEF/LEF**, with
`MAGIC_EXT_USE_GDS=false`, not by `write_cdl` and not by full-GDS PEX.

- `raw_tt_gf_wrapper.spice.gz`: original extraction, before `MergeWellNets`.
- `repaired_tt_gf_wrapper.spice.gz`: final LVS input **after** custom
  extracted-netlist modifications. Do not mistake this for independent
  evidence of physical connectivity.
- `tt_mux.spice.gz`, `tt_ctrl.spice.gz`: the hardened macro extractions from
  the same run. Their leaf standard-cell subcircuits are also abstracts.
- `modules_placed.yaml`: exact placement list from that run.
- `full_gds_extract.tcl`: **candidate, not yet validated** raw full-GDS
  Magic extraction script; source it inside a Magic session initialized
  with the matching GF180 PDK. It requires `FULL_GDS_INPUT`, `FULL_GDS_TOP`
  and a newly created empty `FULL_GDS_OUTDIR`, and does not invoke the
  custom netlist repair.

The original top has 96 extracted ports (including duplicates), 501 elements,
and **29 distinct empty referenced subcircuits** including both SRAM banks,
all ten `tt_mux` instances, the controller, power gates, user tiles and
standard-cell instances. Feeding that file alone to ngspice does not simulate
the actual chip.

The raw top extraction places `sram_lo/q[22]` on `vssd2`, the SRAM's ground
net. This is an **extracted-netlist observation**, not proof of an actual
silicon short: LEF abstraction or extraction may be responsible. The
`MergeWellNets` step rewrites this association using the DEF; it must not be
silently substituted into a supposedly independent physical test.

The compiler SRAM schematic provided in `../SP6TSRAM256x32.spice` cannot be
blindly used to replace the top's SRAM black box: both have 79 identically
named pins, **but their positional order differs**. A name-verified adapter
is required, and it would produce a hybrid compiler-schematic simulation,
not a full-GDS extraction.

The exact placement in this run contains **no `uses_sram: true` user tile**.
It is therefore not possible to issue SRAM requests through the normal
user-tile interface from chip pads on this particular build. A real
whole-chip SRAM test needs a built, physically placed SRAM exerciser tile
or explicitly documented internal test stimulus; the latter cannot prove
the external user-tile path.

## Reproduce the fail-closed audit

From this directory:

```sh
python3 test_audit_spice.py
python3 audit_spice.py artifacts/raw_tt_gf_wrapper.spice.gz
python3 audit_spice.py artifacts/raw_tt_gf_wrapper.spice.gz \
  --library artifacts/tt_mux.spice.gz \
  --library artifacts/tt_ctrl.spice.gz \
  --library ../SP6TSRAM256x32.spice
```

Both audits intentionally return failure. The second adds the real
macro-level mux/controller extractions and compiler SRAM schematic but
still reports missing/empty physical masters, the SRAM port-order mismatch,
and the extracted `q[22]` association. Empty decorative/filler cells may be
legitimately nonfunctional; each needs a documented waiver or model before
declaring the circuit complete. This conservative tool does not perform
automatic waivers, modify connections, or claim its checks are LVS.

## Requirements for the actual test

1. Select the exact GDS/ODB and matching PDK release; obtain a raw full-GDS
   extraction and/or OpenROAD `write_cdl` with real, matching master
   netlists. `write_pg_spice` exports only the PDN, not the full circuit.
2. Supply transistor models for the standard cells, SRAM, power gates and
   actual user macros; resolve name/port order and power/well connections
   without masking shorts. Document whether each view is schematic, raw
   extracted, or post-layout with parasitics.
3. Resolve the `q[22]` extraction discrepancy independently and run
   unmodified physical LVS before trusting any whole-chip circuit.
4. Build an SRAM-capable test tile and test control/addressing, isolated
   read/write and masks, both banks, bit 22, and non-SRAM tiles from the
   real chip interface at safe 3.3 V. Avoid asserting the external input
   and output drivers simultaneously.
5. Run ngspice or a suitable hierarchical/mixed-signal simulator with the
   real PDK models. The full transistor count is large; resource limits and
   power/package assumptions must be recorded. A smoke test on empty
   subcircuits is not a valid substitute.

References: [OpenROAD `write_cdl`](https://openroad.readthedocs.io/en/latest/main/src/README.html)
and [OpenROAD PDN SPICE](https://openroad.readthedocs.io/en/latest/main/src/psm/README.html).
